Next comes a very delicate and painstaking task to consolidate multiple repositories *not* created from the LaTeX template into only two new repositories that follow the template overall structure and conventions. One of the new repositories `QuantumDI` will consolidate repositories in `~/repos-DI` be for for my co-authored projects with Iovino; another `QuantumTeam` will consolidate repositories in `~/repos-q-team`: those current projects involve more coauthors than just Iovino as well as students. Neither of these two repositories exists yet.

The consolidation requires careful planning, and will probably need to be done in steps. I think it is better first to “convert” each individual repository to the template / vendored model, and then carefully move each of the redone repositories to populate a subdirectory of the respective `Quantum…` repository. In that way, each intermediate change to the existing repositories will be meaningful by itself, can be tested in-place, ensuring that it follows necessary consolidated repo conventions; after that, it will remain only the relatively minor task of populating the two new repositories with the many migration-ready ones.

Start by pulling all latest changes from all repos in `repos-DI` and `repos-q-team`.

The in-place per-repo changes should be purposeful and orchestrated per the following guidelines:
- Run a full analysis and comparison of the macros used and re-used in all consolidated TeX files. Create new or adapt existing `.sty` files in master repository `~/repos/LaTeX-shared-files` so as to capture shared macro and style definitions of closely related documents. Duplicate or redundant macro definitions should be removed; macro name changes to achieve naming consistency should be deployed across all documents. Prefer the macro naming conventions per the shared-files repository.
- A coherent naming scheme should be used for the root directories and TeX files throughout.
  - For TeX files the convention is: underscore-separated words, with proper names capitalized, e.g., `Soler_axioms.tex` (the convention is inconsistently applied).
  - The subfolder names should also be consistent; the current names of repositories are extremely inconsistent.
  - The name changes should *not* be done while doing the preparatory work in the multiple current repositories; it is better to keep the old names “as is”; in the newly created repositories `Quantum…`, the files should be renamed to follow the uniform convention.
  - Subject to revision and approval before final migration, a list (probably JSON or Yaml format are appropriate) should be created to map the folder and file renamings (old -> new) in the transition from existing to new consolidated repositories. Some such renamings should be as follows:
    - The repositories `Quantum_stability`, `Quantum_NIP` and `Quantum_simple_unstable` form a three-part sequence that should be renamed  `Qbipartite_1_stability`, `Qbipartite_2_NIP` and `Qbipartite_3_simple_unstable` (both the root directory and name of main `.tex` file, respectively.)
    -  Repository `Quantum_logic` and name `Bell-Kochen-Specker` of main TeX file should become `hidden_variables`.
    -  The repositories `Stability`, `Games`, `LogicTextbookUTSA` and `DiscreteMathTextbookUTSA` each contains a textbook in progress. The new directories should become `book_logic_of_dependence`, `book_combinatorial_and_topological_games`, `book_quantum_logic` and `book_contemporary_discrete_mathematics`, respectively. The main TeX files should be named equally, but with the name prefix `book_` becoming a name suffix `_book` instead.
- Labels (for chapters, sections, equations, etc.) must be renamed to adhere to the template’s conventions. Fixing nontrivial problems with orphaned or missing labels is not a priority, although obvious problems such as mistyped labels should be fixed.
- All documents should be semantically re-flowed and obsolete TeX code (e.g., non-Unicode diacritics) replaced as per the scripts in the template.
  - Non-semantic hard line breaks that have been introduced in large portions of many of the documents (e.g., at column 80, or simply mid-sentence), will need to be eliminated manually prior to reflowing semantically.
  - Comments should follow template conventions.
    - Add standard-formatted comment headers (as per the template) for major logical units: document, chapter, section, etc.
- All TeX files having a list of references at the end should generate it from the same BibTeX vendored from `~/repos/math-bibliography`. The file `references.bib` should be augmented with any entries necessitated by the consolidation. All references labels must adhere to the “house style” conventions dictated by the `math-bibliography` repository. For any paper having an in-place by-hand list of references at the end, create a bibliography style for BibTeX that reproduces the by-hand results if necessary to generally keep the same printed output (the in-place reference list should be removed).
- It is acceptable to slightly change the exact printed contents of the list of references if necessitated by the requirement of automatic BibTeX generation. It is also acceptable to change minor styling of closely related documents (e.g., the "Qbipartite_…`) to achieve more consistency in cases of existing divergence. These minor changes necessitated by the BibTeX automation and consistency of styling are the *only* acceptable changes to the printed (PDF) output. (Other changes may be acceptable if technically challenging to keep the verbatim requirement, but consult with me before deciding.)
- Obsolete, orphaned or empty files should not be part of the new `Quantum…` repositories (e.g., `~/repos-q-team/Stability/tmp1.tmp` and `~/repos-q-team/Stability/tmp2.tmp`).
